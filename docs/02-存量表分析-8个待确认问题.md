| 维度 | 存量共享表 | 战略客户部表 |

### 💡 关键洞察

**两个表是"上下游"关系**：
- **战略客户部表** = 战略客户部**自己提的**签名清单（半结构化、按"签名来源文件"分批）
- **存量共享表** = 真真部门**汇总的**所有签名（结构化、有报备结果）

**两个表的数据有重叠**（比如"湖北税务/77/3228"），但**不是同一份数据**——共享表更全，战略客户部表更新。

### 关于存量共享表

**A. "申请人"列到底装的是什么？**
- 我看到的：联电 R2 = `金华`、R8 = `丹纯`、广东移动 R2 = `陈朗`
- 有的像**人名**（陈朗），有的像**部门/区域**（金华、丹纯）
- → 这影响我们的"提交人"字段怎么设（是 user_id 还是 dept_id）

**B. "业务大类/业务细类" 的枚举值都有哪些？**
- 联电样本全 `77`/细类 `2`、视频短信样本全 `游戏营销`、广东移动样本全 `55`/细类 `1`
- 我需要**完整的枚举列表**（77/55/554 之外还有哪些？视频短信的中文类目都叫啥？）
- → 不然表单无法做下拉

**C. "需要报备端口" 字段怎么解析？**
- 联电 R2: `3228`（纯数字）
- 其它移动 R2: `1582（3，2）`（端口+括号描述）
- 广东移动 R3: `4915、4530（3，2）`（多端口+括号）
- → 这是**"1 个字段装多个含义"**，可能需要拆成多列（端口号 / 数量 / 描述）

### 关于战略客户部表
