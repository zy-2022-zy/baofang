## 一、模型全景

```
┌─────────────────┐         ┌──────────────────┐
│  channel_list   │         │   demand_batch   │
│  (全盘通道清单) │         │   (需求批次)      │
│  -- 导入的真真表│         │   -- 一次提单行为  │
└────────┬────────┘         └────────┬─────────┘
         │ 1:N                      │ 1:N
         │ H 字段 → C 列后4位查询    │ 共享 batch_no
         │                          │
         │         ┌────────────────▼──────────┐
         │         │  demand (子需求)           │
         └────────►│  port_id (4位)            │
                   │  carrier (运营商)          │
                   │  region  ← 查 channel     │
                   │  handler ← 查 channel     │
                   └────────┬──────────────────┘
                            │ N:1
                            │
                   ┌────────▼──────────────────┐
                   │  rejection_log            │
                   │  (驳回表 - 第1块只读)       │
                   └───────────────────────────┘
```

**3 张核心业务表**（channel_list / demand_batch / demand）+ 1 张辅助表（rejection_log）+ 1 张用户表（mock 5 人）

## 二、5 张表详细定义

### 2.1 `channel_list` 全盘通道清单（真真导入）

**来源**：真真发的「移动短信通道清单_20241025.xlsx」（含移动/联通/电信/视信/5G）

| 字段 | 类型 | 来源列 | 必填 | 说明 |
|------|------|--------|------|------|
| `id` | INTEGER PK | 自增 | ✅ | |
| `port_code` | TEXT | C 通道号码 | ✅ | **8 位完整主端口**（如 `10693228`） |
| `port_id` | TEXT | （派生） | ✅ | **port_code 后 4 位**（如 `3228`）—— 索引列 |
| `channel_name` | TEXT | D 通道名称 | ✅ | `佛山移动(ADC)_10681598` |
| `channel_category` | TEXT | E 通道分类 | ✅ | 短信 / 视信 / 5G |
| `region` | TEXT | F 供应商简称 | ✅ | 佛山 / 东莞 / 揭阳 / 福州…… |
| `carrier` | TEXT | G 运营商 | ✅ | 移动 / 联通 / 电信 |
| `info_type` | TEXT | H 信息类型 | ❌ | 短信 / 视信 |
| `is_finance` | BOOLEAN | I 是否金融行业 | ❌ | 是 / 否 |
| `report_handler` | TEXT | J 报备人 | ✅ | 雷杏仪 / 陈朗…… |
| `source_channel_id` | INTEGER | A 通道id | ❌ | **真真部门内部 ID，现阶段忽略**（导入时跳过） |
| `created_at` | DATETIME | | ✅ | 入库时间 |

**索引**：
- `UNIQUE(port_code)` —— 8 位主端口唯一
- `INDEX(port_id, carrier)` —— **核心查询键**（H 字段值 + 运营商）

**主键/唯一键**：port_code（8 位）唯一

**导入方式**：
- 真真上传 Excel → 后端解析 → 全量覆盖写入
- 每次导入重置表（不带 valid_from/valid_to，按真真说"手工维护最新版"）

### 2.2 `demand_batch` 需求批次表（一次提单行为）

**来源**：系统生成，真真提一次单 = 1 条

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | INTEGER PK | ✅ | |

| `biz_line` | TEXT | ✅ | `realname`（本期只做这一条业务线） |
| `submitter_id` | INTEGER | ✅ | 关联 user.id |
| `submitter_dept` | TEXT | ✅ | 5 部门之一 |
| `sub_demand_count` | INTEGER | ✅ | 拆出多少条子需求 |

| `force_submitted` | BOOLEAN | ✅ | 是否强制提交 |
| `status` | TEXT | ✅ | `submitted` / `partial_done` / `all_done` |
| `raw_payload` | JSON | ✅ | 原始表单数据（审计用） |
| `created_at` | DATETIME | ✅ | |

**索引**：

### 2.3 `demand` 需求子需求表（拆行后）

**来源**：系统生成，**每条子需求 = 1 个主端口 + 1 个运营商**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | INTEGER PK | ✅ | |
| `batch_no` | TEXT | ✅ | 关联 demand_batch.batch_no |
| `port_id` | TEXT | ✅ | **主端口后 4 位**（单值，不是数组） |
| `carrier` | TEXT | ✅ | 移动 / 联通 / 电信 |
| `sub_port_count` | INTEGER | ✅ | **默认 1**（无括号时 = 1） |
| `extension_count` | INTEGER | ✅ | 拓位数（默认 0） |
| `region` | TEXT | ✅ | **从 channel_list 查询得到**（真真不需要手填） |
| `report_handler` | TEXT | ✅ | **从 channel_list 查询得到**（真真不需要手填） |
| `business_category` | TEXT | ✅ | 业务大类：`77` / `55` / `游戏营销` 等 |
| `business_sub_category` | TEXT | ✅ | 业务细类：`1` / `2` / `4` |
| `company_name` | TEXT | ❌ | 实名企业名称（共用模板 A 的字段） |
| `use_case` | TEXT | ❌ | 用途/业务说明 |
| `initial_check_warned` | BOOLEAN | ✅ | 是否被初判警告 |
| `initial_check_reason` | TEXT | ❌ | 警告原因 |
| `force_submitted` | BOOLEAN | ✅ | 是否强制提交（带警告时勾选） |
| `status` | TEXT | ✅ | `pending` / `initial_checked` / `assigned` / `reporting` / `done` / `failed` |
| `created_at` | DATETIME | ✅ | |
| `updated_at` | DATETIME | ✅ | |

**索引**：
- `INDEX(batch_no)` —— 按批次查子需求
- `INDEX(port_id, carrier)` —— 按端口+运营商查
- `INDEX(status)` —— 按状态过滤

**关键查询**（端口解析）：
```sql
-- 已知 port_id + carrier，查 channel_list 得到 region + report_handler
SELECT region, report_handler
FROM channel_list
WHERE port_id = ?  -- H 字段值（如 3228）
  AND carrier = ?  -- 移动/联通/电信
LIMIT 1;
```

## 三、表关系图

```
channel_list (主表，真真导入)
  └─ (port_id + carrier) ──→ demand.port_id + demand.carrier
                            （查 region / report_handler）

demand_batch (总单)
  └─ batch_no ──→ demand.batch_no （N 条子需求共享批次号）

rejection_log (独立表)
  └─ (signature + carrier) ──→ demand.warning 判定

user (独立表)
  └─ submitter_id ──→ demand_batch.submitter_id
```

## 四、第 1 块数据流（端到端）

```
[真真打开网页]
  ↓
[选择 mock 用户登录] → user 表
  ↓
[进入提需求页] → 前端动态渲染表单
  ↓
[填表：biz_line + 动态加行(port_id, carrier, 业务大类, 业务细类)]
  ↓
[点提交]
  ↓
[后端 POST /api/demands]
  1. 生成 batch_no = B{today}-{6位序号}
  2. 逐条 demand 查 channel_list → 得 region + report_handler
  3. 逐条 demand 查 rejection_log → 得 warning
  4. 写 demand_batch + N 条 demand
  5. 返回 { batch_no, sub_demands, warnings }
  ↓
[前端：弹警告窗（若有）→ 跳批次详情]
```
